# v1.0.0-rc.3.0 qualification record

Status: candidate source qualification; no RC.3.0 tag or release created.
RC.2.4 remains the published Homebrew baseline while RC.3.0 is qualified.

## Required source checks

Run from a clean checkout with isolated PromptGrinder and Go state:

```sh
PROMPTGRINDER_HOME="$(mktemp -d)" GOCACHE=/tmp/promptgrinder-go-cache go test -shuffle=on -count=1 ./...
PROMPTGRINDER_HOME="$(mktemp -d)" GOCACHE=/tmp/promptgrinder-go-cache go test -race -count=1 ./...
GOCACHE=/tmp/promptgrinder-go-cache go vet ./...
go mod verify
test -z "$(gofmt -l .)"
git diff --check
```

The candidate must build the real CLI and verify `--version`, `--help`, single
work-order validation, complete folder validation, dry-run, JSON, and exit-code
behavior without invoking a real AI service or GUI terminal.

Cross-build `darwin/arm64` and `darwin/amd64` with `CGO_ENABLED=0` and
`-trimpath`. Both outputs must be nonempty Mach-O executables; only the native
artifact is executed during local qualification.

## Compatibility review

- Existing `.md` work orders retain their parsing, ordering, dependency, and
  execution behavior.
- `.pg` is an additive extension for the same Markdown body and YAML
  frontmatter contract; it does not introduce a new persisted schema.
- `validate <folder>` uses the established run-folder preflight, and
  `validate-folder` remains a backward-compatible alias.
- Human folder validation adds a checked slice/tool/model list. JSON adds the
  optional `prompt_validations` field without removing existing fields.
- Folder validation does not create workers or sequence state.
- No compiled release archives are restored.

Exact clean-machine macOS, Codex, Terminal.app, and iTerm2 qualification
remains a human release gate after merge and before tagging.
