# PromptGrinder v1.0.0-rc.2.1 release notes — candidate

Status: release-prepared candidate; not tagged, qualified, or published.

The source binary reports `v1.0.0-rc.2.1`. No RC.2.1 release artifact exists
until the annotated tag workflow completes.

## Fixes

- Ordered `run-folder` execution now continues to the final Codex agent message
  when an earlier JSONL command event contains large aggregated output. The
  parser accepts bounded records up to 16 MiB instead of silently stopping at
  the scanner's 64 KiB default.
- Worker completion evidence is saved before terminal status becomes visible,
  so sequence polling cannot classify a successful worker using stale or
  missing completion fields.

These fixes address false `missing or malformed STATUS field` failures where
the worker log did contain the required final `STATUS: PASS` and
`NEXT_PROMPT_SAFE: yes` contract.

## Compatibility

RC.2.1 is a compatible runtime bug fix for RC.2. Commands, prompt formats,
configuration, and persisted schemas are unchanged. Existing state remains
readable. The 16 MiB per-record parser limit is intentional and bounded.

## Upgrade and rollback

Preserve `${PROMPTGRINDER_HOME:-$HOME/.promptgrinder}` and replace only the
binary. Run `promptgrinder doctor` and a representative foreground folder run.
Rollback by restoring the previous verified binary; no state migration is
required.

## Publication gates

- formatting, vet, ordinary tests, race tests, and release workflow checks;
- regression verification with a JSONL command event larger than 64 KiB;
- Darwin arm64 and amd64 artifact verification and native smoke execution;
- clean-machine evidence and explicit maintainer approval before tagging or
  publication.
