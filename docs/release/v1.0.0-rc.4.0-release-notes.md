# PromptGrinder v1.0.0-rc.4.0 candidate notes

Status: candidate source; not tagged or published. RC.2.4 remains the
published Homebrew version during qualification.

RC.4.0 lets a run-folder declare deliberate Codex context boundaries without
splitting one ordered implementation plan into separate folders.

## Highlights

- Runnable work orders accept `context_mode: shared` or `context_mode: fresh`.
  `shared` is the compatible default and resumes the preceding runtime session
  when supported.
- `fresh` launches the marked slice without the preceding session ID. The shared
  specification, current repository state, and slice policy remain
  available, so durable handoffs replace conversational carry-over.
- A successful fresh slice provides the session that subsequent shared slices
  continue, allowing explicit reset boundaries inside one dependency-aware
  folder.
- Invalid context modes fail strict frontmatter validation before any sequence
  state or worker is created. Sequence records retain the selected mode for
  inspection.
- The task-frontmatter semantic preamble is now v3, and the slice DSL and
  use-case catalog document the reset behavior.

## Distribution

GitHub releases remain source-only. Committing or merging this candidate does
not create a tag, publish a release, or update the Homebrew tap.
