# PromptGrinder v1.0.0-rc.4.2 candidate notes

Status: candidate source; not tagged or published.

RC.4.2 makes interrupted run-folder recovery truthful and non-destructive.

## Highlights

- A worker with explicit `client disconnection detected` runtime evidence can
  consume one configured recovery attempt without advancing the sequence.
- Known worker scope, engine/model, worker ID, log path, and completion
  evidence remain attached to the failed sequence item if recovery cannot
  continue.
- Before a clean-baseline retry, PromptGrinder isolates only changes proven to
  be owned by that slice in a durable recovery artifact. It does not use reset,
  clean, stash, broad process termination, or an automatic partial commit.
- Compiler/test failures, completion-contract failures, cancellation, timeouts,
  policy violations, and ambiguous changes remain non-recoverable.

## Distribution

GitHub releases remain source-only. Committing or merging this candidate does
not create a tag, publish a release, or update the Homebrew tap.
