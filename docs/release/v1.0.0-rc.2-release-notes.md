# PromptGrinder v1.0.0-rc.2 release notes — candidate

Status: release-prepared candidate; not tagged, qualified, or published.

The source binary reports `v1.0.0-rc.2`. No RC.2 release artifact exists until
the annotated tag workflow completes. Do not use these notes as an availability
announcement before publication.

## Highlights

- Persistent project-owned named workers with identity, task queues, scheduling,
  lifecycle controls, path/worktree policy, retained attempts, and local review
  handoffs.
- Runtime-neutral named-worker launch with Codex and Antigravity adapters.
- Deterministic `promptgrinder discover` generation of
  `.promptgrinder/project.yaml`, role YAML, and context directories without
  overwriting existing files.
- Review-first `promptgrinder roles enhance` with repository-grounded structured
  recommendations and explicit selected/all apply controls.
- Foreground ordered-folder UI with prompt inventory, spinner and elapsed time,
  worker/log details, sequence status commands, plain mode, and immediate errors.
- Strict ordered completion requiring exactly one `STATUS: PASS` and
  `NEXT_PROMPT_SAFE: yes`; clarification, blocked, partial, malformed, duplicate,
  missing, or unsafe results stop the sequence and retain their reason.
- Strict semantic frontmatter, exact rendered-prompt inspection through
  `validate --render`, and ordinary-worker allowed/forbidden path enforcement.
- Safe automatic commits that require a clean baseline, stage only attributed
  paths, detect races, and never capture unrelated PromptGrinder or user files.
- Compiled CLI acceptance tests, stronger GitHub CI, shell-aware doctor PATH
  remediation, and repository-local PromptGrinder development skills.

## Compatibility

RC.2 keeps RC.1 public state and configuration readable. JSON objects may gain
fields for timestamps, completion details, runtime evidence, and discovery or
role recommendations. Existing meanings are unchanged.

One-off `run` and `run-folder` continue to use Codex. Named-worker definitions
select Codex or Antigravity symbolically without changing role identity.
PromptGrinder remains local-first and never pushes, merges, tags, publishes, or
contacts an AI service during deterministic discovery.

Unknown frontmatter keys now fail instead of being silently discarded. Ordered
success now requires the explicit semantic completion contract. These are
intentional safety corrections; old prompt folders may need their instructions
moved into the Markdown body and the completion fields added.

## Supported candidate matrix

- macOS Darwin arm64 and amd64 artifacts;
- Terminal.app, iTerm2, and headless adapters;
- Codex CLI for one-off work and named workers;
- Antigravity (`agy`) for named workers where installed and configured.

Exact macOS, Codex, Antigravity, Terminal.app, and iTerm2 versions require the
clean-machine qualification record before publication. Artifacts remain unsigned
and not notarized; Homebrew, Linux, Windows, and automatic updates are unsupported.

## Upgrade and rollback

Preserve `${PROMPTGRINDER_HOME:-$HOME/.promptgrinder}` and replace only the
binary. Run `promptgrinder doctor`, inspect existing workers and sequences, and
perform a read-only smoke run. Roll back by restoring the previous verified
binary; retained local state must remain readable or fail with precise guidance.

## Publication gates

- full ordinary/race/vet/module/format/acceptance suite;
- Darwin arm64 and amd64 artifact verification plus native smoke execution;
- clean-machine onboarding and runtime matrix evidence;
- documentation, compatibility, secret/private-prompt, and tracked-file review;
- explicit maintainer approval for version change, annotated tag, push, and
