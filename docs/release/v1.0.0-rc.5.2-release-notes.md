# PromptGrinder v1.0.0-rc.5.2 candidate notes

Status: candidate source; not tagged or published.

## Highlights

- Run-folder failures can carry an optional structured report: failure type,
  concise summary, independent blocking checks, evidence-report path, and next
  action. Foreground output and sequence JSON retain the same evidence without
  changing completion, checkpoint, or resume semantics.
- Declared capability-gate audits now retain the exact `BLOCKED` / `no`
  completion through the runtime boundary. Their permitted evidence can be
  checkpointed and their dependent implementation slices remain blocked.
- A validation-only sequence selected by `--resume` now recommends an explicit
  `--fresh` run instead of an unusable second resume command.
- Documentation now prominently states the qualified macOS, terminal, and
  runtime-adapter surface, and the baseline slice template explains when broad
  module ownership versus narrow path grants is appropriate.

## Distribution

GitHub releases remain source-only. After the annotated tag is qualified, the
release workflow creates a draft GitHub prerelease. Publishing that prerelease
opens a reviewable source-based formula update pull request in the Homebrew
tap; neither a branch push nor a draft release updates the tap.
