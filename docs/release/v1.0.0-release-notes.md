# PromptGrinder v1.0.0 release notes — candidate

Status: final-version pull request; not tagged or published.

PromptGrinder v1.0.0 is a local-first orchestration CLI for deterministic,
reviewable engineering work through replaceable AI runtimes. PromptGrinder owns
worker identity, tasks, policy, lifecycle, state, worktrees, queues, and review
evidence; configured runtimes execute the work.

## Highlights

- Run validated Markdown work orders individually or as ordered, resumable
  folders with shared context, explicit completion contracts, live status, and
  retained evidence.
- Define persistent project workers with allowed paths, runtime-neutral launch
  requests, task queues, lifecycle controls, review handoffs, and safe Git
  boundaries.
- Discover repository technologies and minimal roles deterministically, then
  request grounded, reviewable AI-assisted role enhancements without silently
  overwriting user configuration.
- Use Codex or Antigravity for named workers while retaining PromptGrinder as
  the runtime-independent source of truth.
- Verify setup with `doctor`, inspect sequences and workers, use stable plain or
  JSON output, and run without hosted PromptGrinder infrastructure.
- Start an unconfigured installation with a clear setup handoff; setup performs
  a read-only inventory of supported CLIs, terminal applications, Git, shell,
  PATH, and local storage before proposing confirmed writes.

## Distribution

GitHub releases contain only GitHub's automatic tagged-source ZIP and tar.gz
links. PromptGrinder does not upload compiled binary archives or binary-only
checksum assets. The supported macOS installation path is Homebrew:

```sh
brew tap promptgrinder/tap
brew install promptgrinder
```

After the GitHub release is published, separate automation proposes the exact
`v1.0.0` source URL, explicit `1.0.0` version, and SHA-256 in a Homebrew tap pull
request. Tap CI and maintainer review are required; the formula PR is never
auto-merged.

## Compatibility and limits

The v1 CLI, successful task format, JSON meanings, repository configuration,
and persisted-state contracts follow the compatibility policy in
[`docs/RELEASE_POLICY.md`](../RELEASE_POLICY.md). Existing RC state remains
readable and no migration is required.

macOS on Apple silicon and Intel is the supported platform family. Exact
clean-machine macOS, Codex, Terminal.app, and iTerm2 versions must be recorded
in the final qualification evidence before publication. Linux and Windows are
not supported by v1.0.0.

## Publication boundary

Merging the version-bump pull request does not create a release. A maintainer
must separately authorize the annotated `v1.0.0` tag and publish the draft
release only after the final gate is approved.
