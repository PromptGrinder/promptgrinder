# PromptGrinder v1.0.0-rc.3.0 candidate notes

Status: candidate source; not tagged or published. RC.2.4 remains the
published Homebrew version during qualification.

RC.3.0 makes PromptGrinder work orders more explicit and makes complete folder
validation available through the primary `validate` command.

## Highlights

- Work orders may use `.pg` to identify PromptGrinder slices or `.md` for
  conventional Markdown tooling. Both extensions use the same Markdown body,
  YAML frontmatter, ordering, dependency, role, and path-policy rules.
- `run`, shared-context discovery, and `run-folder` accept `.pg` and `.md`
  work orders without changing ordering or sequence-state semantics.
- `promptgrinder validate <folder>` runs the complete ordered-folder preflight
  without launching workers or creating sequence state.
- `validate-folder` remains available as a backward-compatible alias and
  accepts the same folder policy overrides.
- Folder validation prints a checked list of runnable slices with each resolved
  execution tool and model, followed by the resolved ordered sequence.
- JSON folder validation includes additive per-prompt validation results for
  automation consumers.
- The Slice DSL, use-case catalog, command reference, and examples document the
  new extension and unified validation workflow.

## Distribution

GitHub releases remain source-only. Committing or merging this candidate does
not create a tag, publish a release, or update the Homebrew tap.
